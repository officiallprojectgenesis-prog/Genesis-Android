# World, Objects & Environment

3D objects, world weather, game time, water levels, gravity, minute duration, heat haze, explosions, fires, garage doors, searchlights, and foliage.

## Parity Status

- **Total Functions:** 227
- **Implemented:** 227 (100.0%)
- **Stubs:** 0
- **Missing:** 0

> **Technical Requirement:** Weather, clock, and clip distances are stored. Object calls follow CLuaObjectDefs: a resource and a stock object model create a client element, and CObject is not spawned. Break, gang-tag alpha, and texture replace fail closed. Zones, scripted water, managed fires, and buildings are stored. Line-of-sight, roof, and screen projection return the desktop failure result because those engine calls are not hooked. Garage geometry and world-model removal counts still need their engine data. `setAmbientPedPopulationZoneState` checks the desktop label and table rules, then returns false because `FindZoneByLabel` is not hooked. The other ambient calls return the same desktop failure (`inactive`, `invalid-origin`, `population-unavailable`, `unsupported-model`, or false). `isWorldRPGMobilePopulation` stays true until those hooks exist, and the traffic scripts keep the puppet and polyfills while it does. Host-tested. Not yet run on a device.
